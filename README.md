# 赛博元芳 · 匿名纠结评判广场（微信小程序）

> 「元芳，你怎么看？」——把你的纠结匿名发到广场，让素不相识的路人帮你拍板：**通过，去做**；**驳回，再想想**。
> 界面与交互体系对齐「钱包请等等」，业务改为通用的"纠结选择"评判。

**当前为原生微信小程序本地演示版。** 无需 npm 安装或前端构建，导入微信开发者工具即可预览；尚未接入后端和跨设备数据共享。源码内预置 10 条示例选择，设备上产生的发布与投票保存在本地存储中。

## 功能总览

| 页面 | 说明 |
|---|---|
| 首页 | 时间问候 + 匿名身份（纠结者XXXXXX）、收到评判总览与采纳率、进行中的评判提醒、累计通过/被驳/帮人拍板、每日纠结语录 |
| 广场 | 信息流（最新 / 即将揭晓 / 已揭晓）、通过·驳回投票、倒计时进度条、分页加载、下拉刷新、回顶部、举报/删除 |
| 发布 | 标题 + 纠结理由 + 选填 B 计划 / 预计花费 + 分类（消费/职业/感情/学业/生活/其他）+ 评判时长（2/6/24 小时），提供字数提示与缺失项提示 |
| 我的 | 匿名身份卡、统计、累计省下金额 / 获批开销、我的发布 / 我的投票两个列表 |
| 详情 | 单条选择完整信息、时间线、投票或结果、删除/举报、转发好友帮拍板 |

## 核心机制（继承自「钱包请等等」的精髓）

- **匿名**：发布者只显示「一位陌生人」+ 绿色问号头像，无任何身份信息。
- **先投后看**：投票或揭晓之前，只能看到"已有 N 人表态"，看不到票数倾向——保证第一真实判断，不被热门倾向带节奏。
- **倒计时自动结束**：2 / 6 / 24 小时，进度条展示流逝比例，到点自动按票数得出「通过 / 驳回 / 平票」。
- **按匿名身份限制投票**：同一本地匿名身份对每条选择只能投一次，不能投自己或已结束的选择；当前不提供真实用户认证。
- **举报模型**：同一匿名身份对同一条只计一次举报，累计 3 个不同身份举报后自动隐藏；当前仅作用于本地数据。
- **金额统计**：本人已揭晓的金额帖，驳回票更多计为省下，通过票更多计为获批开销；平票和无金额帖不计入。

## 数据层说明（重要）

当前为**本地演示版**：数据存在手机本地存储（`wx.setStorageSync`），首次启动预置 10 条生动的种子选择（含进行中与已揭晓），可完整体验发布—投票—揭晓—记录全流程。**数据仅本机可见，多用户之间不互通。**

`utils/store.js` 的 API 形态按云端设计（行结构、错误码 `NOT_FOUND/OWN_POST/ENDED/ALREADY_VOTED` 等、统计口径），页面与 `services/` 不直接触碰存储。升级为多用户版的路径：

1. 开通 WorkBuddy 云服务（或自建后端）；
2. 建 `choices / votes / reports / profiles` 四表 + RLS + `cast_vote / my_stats` 两个 RPC（投票原子性、一人一票由数据库保证）；
3. 用所选后端客户端替换 `store.js` 的持久化实现，尽量保持 `services/choices.js` 的调用接口；同时补齐异步请求、登录态、权限和服务端校验，并验证页面交互。

上述云端方案尚未实现。匿名身份由本地随机生成，不是微信登录凭证；清除小程序存储会丢失本机的身份、发布和投票记录，重新初始化会生成种子数据。

## 运行

1. 安装微信开发者工具，导入项目根目录，编译预览；无需执行 `npm install`。
2. `project.config.json` 当前已有具体 AppID，并配置 `libVersion` 为 `3.7.12`。克隆后核对 AppID，按自己的应用修改；文档不复制实际标识。AppID 不是 AppSecret。
3. 需要命令行检查时安装 Node.js，在项目根目录运行：

```bash
node tools/smoke_test.js
node --check services/choices.js
```

冒烟脚本在内存中模拟 `wx` 存储，覆盖种子数据、先投后看、重复投票、发布、删除、举报去重、时间和金额统计，不会操作开发者工具中的真实本地数据。界面与交互仍需在开发者工具中验证。

已有 8 张 tabBar 图标可直接使用。重新生成图标时才需要 Python 与 Pillow，运行 `python gen_icons.py` 会重写 `assets/tabbar/` 中的对应图片。

## GitHub 提交与隐私

根目录 [.gitignore](.gitignore) 已排除 AI 工具记忆和代码索引（`.workbuddy/`、`.codegraph/`）、微信开发者工具本机配置 `project.private.config.json`、真实 `.env` 配置、依赖、Python 字节码缓存和运行日志。不要把其中的个人昵称、登录信息、本机路径、截图记录或用户数据导出复制到 README 和源码中。

`project.config.json` 与其中的 AppID 仍会提交；是否公开应用关联应在发布前确认。`.env.example` 和 `.env.*.example` 只放占位值；当前原生小程序不会自动读取 `.env`，也不能通过客户端文件安全保存 AppSecret。

初始化 Git 仓库后，可在项目根目录核验：

```bash
git check-ignore -v .workbuddy/memory/MEMORY.md project.private.config.json .env.local
git status --short
git diff --cached --name-only
```

`.gitignore` 不会移除已被跟踪的文件，也不控制网页手动上传或压缩包内容。`project.config.json` 的 `packOptions.ignore` 仅控制小程序打包，已排除 README、AGENTS 等开发文档；新增辅助文件后，还需在开发者工具中核对打包清单和代码依赖分析。

开发约定和业务不变量见 [AGENTS.md](AGENTS.md)。

## 从演示版到正式发布

- **后端与身份**：跨设备共享、真实用户身份、投票去重与权限校验尚未实现，需要配套后端。
- **内容安全**：发布页尝试调用 `wx.security.msgSecCheck`，不可用时会放行；这不等于已完成服务端内容审核。
- **隐私说明**：当前本地身份随机生成，不读取微信昵称、头像或位置；接入后端或新增数据收集时同步更新产品隐私说明，并按微信平台届时的发布要求准备资料。
- **分享**：详情页已有 `onShareAppMessage` 配置；当前本地数据不共享，其他设备不能仅凭分享链接读取发送者本地发布的内容。
